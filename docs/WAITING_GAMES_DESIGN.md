# 等待页与小游戏设计方案

状态：讨论稿，可进入原型实现  
版本：0.1  
整理日期：2026-09-03

## 一句话定义

在惊恐发作的几分钟里，用轻松、低压力的小活动帮用户从身体感受之外拿回一小块注意力；感觉可以还在，用户也可以随时停下并回到眼前的生活。

小游戏是陪伴工具，不是治疗、测验或“熬过发作”的必要条件。

## 已确定的方向

- 产品以自助为主，不在急性流程里反复要求用户求助外界；医疗与紧急情况边界保留在安静、次要的位置。
- 游戏可以转移一部分注意力，但不暗示“只要玩好，惊恐就会消失”。
- 语气可以幽默，笑点落在事实、情境或游戏本身，不拿用户和症状开玩笑。
- 不计分、不排名、不连续打卡、不倒计时，也不因答错增加压力。
- 冷知识题答完立刻揭晓正确答案，并用一两句话讲清原因或背景。
- 冷知识共 100 题；用户既可以随机抽题，也可以从题柜里自己选择。
- 只记录哪些题已经看过，不记录答对、答错或正确率。
- 不额外评价用户“学到了什么”，让知识本身完成这件事。
- 成语接龙不做选择题，改为没有标准答案的“三个词，凑一句”。

## 设计目标

1. 用户在十秒内看懂四种活动的差别，并能用一到两次点击开始。
2. 认知负荷低：一屏只做一件事，最多三个答案选项，不要求急性状态下打字。
3. 允许任何结果：答错、忘记顺序、没有想出句子，都不会形成失败状态。
4. 用户随时可以退出；退出不以症状已经减轻为前提。
5. 所有内容离线可用，不上传作答记录，也不建立个人成绩档案。

## 不做什么

- 不把小游戏宣传为惊恐障碍治疗或医学急救。
- 不用游戏结果判断焦虑程度、认知能力或恢复情况。
- 不问疾病、药物、急救、死亡、灾难等可能把注意力重新拉回威胁的题。
- 不用红叉、失败音效、惩罚动画、连续正确数或“再坚持一下”。
- 不自动播放声音、音乐或震动。

## 入口与整体流程

用户点“直接玩小游戏”后，先进入活动选择页，而不是立即开始某一种任务。

```text
想让哪一小块注意力忙起来？

┌ 手忙一点 ────────┐  ┌ 眼睛忙一点 ──────┐
│ 擦开图景          │  │ 亮窗记忆          │
│ 随手擦，不用答对  │  │ 看一遍，再点回来  │
└───────────────────┘  └───────────────────┘

┌ 好奇心忙一点 ────┐  ┌ 想象力忙一点 ────┐
│ 冷知识问答        │  │ 三个词，凑一句    │
│ 猜一个，马上揭晓  │  │ 正经不正经都行    │
└───────────────────┘  └───────────────────┘

              先不玩，回到眼前
```

默认不替用户选择“最合适”的玩法，也不记住上次选择。每张卡只说清活动方式，不承诺效果。

## 四种活动

### 1. 擦开图景

定位：最低认知负荷，让手和眼睛有一件连续、没有对错的事可做。

沿用现有玩法：移动手指擦开雾层，下面出现完整图景。可以随时换一幅，不设置完成百分比，也不要求把画面全部擦开。

保留文案：

- “从哪里开始都可以。”
- “换一幅”

### 2. 亮窗记忆

定位：适合此刻愿意让工作记忆忙一点的用户。

沿用现有的三扇起步、主动加难、原样重播和不计分设计。点错后不显示失败，只恢复同一组顺序。

推荐反馈：

- 点对中途：“接住了，继续。”
- 完成一组：“记住了。下一组还是三扇。”
- 点错：“刚才那组有点滑，再看一次。”

### 3. 冷知识问答

定位：用一个具体、略带意外的事实把注意力引向外部世界。

#### 单题流程

```text
题目
├─ 选项 A
├─ 选项 B
└─ 选项 C
        ↓ 点击任一项后立即揭晓
答案是「……」。
一至两句解释，最多表达一个主要知识点。

[下一题]  [换个玩法]  [先到这里]
```

交互规则：

- 每题三个短选项，点击后锁定本题，立即展开答案说明。
- 答对和答错使用同一个答案标题：“答案是「……」。”
- 正确选项有文字标识和图形标识，不能只靠颜色表达。
- 用户选错的选项保持中性，不变红、不抖动、不消失。
- 解释出现后不自动跳题，由用户决定什么时候继续。
- 默认“随手抽一题”，优先从没看过的题中抽取；也可以选择自然、动物、文化艺术。
- 随机模式跨多次打开都优先避开已看过的题；用户仍可在题柜里主动重看。
- 单题答题页不显示进度、正确率和连续答对数；类别内编号只出现在用户主动打开的题柜中。
- 答案来源放在可选的“看看出处”里，不挤占主要阅读区。

示例：

```text
章鱼有几颗心脏？

[一颗]  [两颗]  [三颗]

答案是「三颗」。
两颗把血送过鳃，一颗送往身体其他部分。
章鱼在心脏配置上相当不节省。
```

#### 一百个小抽屉

冷知识的入口不是一张成绩单，而是一柜 100 个小抽屉。每个抽屉对应一道题：34 个自然、33 个动物、33 个文化艺术。

默认入口保持简单：

```text
冷知识问答

[随手抽一题]
优先抽一个还没看过的。

[自己挑一个]
打开一百个小抽屉。
```

点“自己挑一个”后，先按类别进入，不在急性状态下一次铺出 100 个选择：

```text
[自然 34]  [动物 33]  [文化艺术 33]

┌────┐ ┌────┐ ┌────┐ ┌────┐ ┌────┐
│ 01 │ │ 02 │ │ 03 │ │ 04 │ │ 05 │
└────┘ └─╴──┘ └────┘ └─╴──┘ └────┘
         看过                 看过

看过的小抽屉会留一道纸边。
它只表示见过这道题，不表示答对。
```

题柜规则：

- 每格至少 48 × 48 CSS 像素；窄屏一行五格，较宽屏可以增加列数。
- 格子只显示类别内编号，不提前泄露题目，也不使用锁、奖杯或完成百分比。
- 没看过的是合上的抽屉；看过的露出一小条风铃草蓝纸边，并提供“已看过”的读屏标签。
- 看过的题仍然可以点击重温，不会被锁住。
- 只有用户选择答案、看到解释之后，才把这道题标成看过；仅仅打开题目不算。
- “随手抽一题”先从未看过的题中随机；100 题都看过后，才从全部题目中抽取，并避开最近看过的十题。
- 某一类别全部看过时仍可继续重温，也可以切换类别，不出现“全部通关”。

#### 跨次打开的本地记录

看过的题目 ID 存在当前浏览器的 `localStorage` 中，建议键名为 `anding-card-trivia-seen-v1`。

只保存类似下面的数据：

```json
{
  "seenIds": ["nature-001", "animal-014", "art-008"]
}
```

不保存用户选择了什么、是否答对、用了多久或打开工具的次数。无痕模式、清理浏览器数据或换设备后，标记可能消失；界面应在平静时使用的设置中说明这一点。

平静路线提供“把所有抽屉合上”，确认文案为：“这只会清除看过标记，不会删除题目。”急性流程不放清空入口，避免误触。

### 4. 三个词，凑一句

定位：让想象力忙起来，不检查词汇量，也不要求输入。

一次给出三个相距较远、但能组成画面的词。用户可以只在心里凑一句，也可以先看工具编的版本。

```text
海豹 · 雨伞 · 美术馆

用这三个词凑一句。
正经不正经都行。

[我凑好了]  [你先来]  [换三个]
```

点击“我凑好了”或“你先来”后，展开工具的版本：

> 海豹撑着雨伞走进美术馆，坚持说自己只是来避雨的。

工具的句子只是另一个答案，不评价用户的句子，也不要求两者相似。急性流程不提供文本框；以后若想加入记录或分享，只放在平静时使用的路线中。

首批词组可使用：

| 三个词 | 工具的版本 |
| --- | --- |
| 海豹 · 雨伞 · 美术馆 | 海豹撑着雨伞走进美术馆，坚持说自己只是来避雨的。 |

## 等待页需要一起调整的地方

### 退出不再以“它退了”为条件

主按钮建议改为“我先回到眼前”。旁边保留一句安静提示：“感觉还在，也可以先放下手机。”这样用户不必等到症状减轻，才有资格结束工具。

### 淡化计时

不在页面上持续展示秒表，也不以“一分钟、五分钟、十分钟”播报进度。计时很容易变成身体检查的另一种形式。若内部仍需用时间切换陪伴文案，只在内存中运行，不让数字成为完成标准。

### 游戏始终是可选支路

用户可以从活动中切换玩法、回到等待页，或直接退出。界面不使用“完成游戏后继续”之类的门槛文案。

## 视觉与动效

视觉继续沿用项目现有的深夜植物色，不另做一套喧闹的“游戏皮肤”。

| 角色 | 色值 | 用途 |
| --- | --- | --- |
| 深松林 | `#132823` | 主背景 |
| 抬高松绿 | `#19332C` | 卡片与活动面板 |
| 纸张白 | `#F2EBDD` | 主文字 |
| 海玻璃绿 | `#77AB90` | 可操作、正确答案 |
| 风铃草蓝 | `#AEBFD9` | 键盘焦点、答案纸条 |
| 雾灰绿 | `#91A99E` | 次要说明 |

字体全部使用本地可用字体，保持离线和快速打开：

- 活动标题：平台圆体优先，字重 700；没有圆体时回退到现有系统中文字体。
- 正文与选项：沿用系统无衬线字体，16px 起，不使用全大写英文装饰。
- 来源与类别：只做信息层级，不缩小到难以阅读的“角标字”。

这组新界面的识别点是一柜 100 个小抽屉。看过的抽屉会露出一小条纸边；答题后，“世界的小纸条”从正确选项下方轻轻展开，像自然观察或博物馆藏品签。抽屉和纸条是一套完整隐喻，取代烟花、勋章和庆祝音效。减少动态效果时，纸条直接出现。

## 语言规则

可以：

- 对事实做轻微、具体的调侃，例如“章鱼在心脏配置上相当不节省”。
- 承认普通失误，例如“刚才那组有点滑，再看一次”。
- 给用户选择，例如“你先来”“换三个”“先到这里”。

不可以：

- “你答错了”“挑战失败”“这么简单都不会”。
- “太棒了”“击败惊恐”“你已经恢复了”等未经用户感受确认的判断。
- 用一句统一收尾替用户总结今天获得了什么。
- 把疾病、身体感受、求助行为或用户本人当成笑点。

## 内容数据结构

题库和词组都打包在应用内，不在急性流程中联网取题。

```js
{
  id: "nature-001",
  number: 1,
  category: "nature",
  prompt: "金星自转一圈和绕太阳一圈，哪个更久？",
  choices: [
    { id: "orbit", label: "绕太阳一圈" },
    { id: "rotation", label: "自转一圈" },
    { id: "same", label: "两者一样久" }
  ],
  answerId: "rotation",
  explanation: "金星自转一圈约 243 个地球日，绕太阳一圈约 225 个地球日。",
  source: {
    title: "NASA · Venus Facts",
    url: "https://science.nasa.gov/venus/venus-facts/"
  },
  verifiedOn: "2026-09-03",
  status: "reviewed"
}
```

实现时用 `answerId` 判断，不依赖选项位置。首批答案位置人工均衡，暂不在每次展示时重新打乱，以便复核文案和自动化测试。

题目的 `id` 和类别内 `number` 发布后保持稳定，题柜才能正确识别用户看过哪一格。小幅修正文案可以沿用 ID；若问题含义或答案发生变化，则分配新 ID，旧题进入 `retired` 状态。

三词造句使用类似结构：`id`、`words`、`example`、`status`。词组与示例必须成套审核，不在急性流程里实时生成内容。

## 题库标准

每道题进入产品前需要满足：

1. 有一个明确、可靠且可直接访问的来源，优先科研机构、博物馆、文化遗产机构或原始研究团队。
2. 只有一个无歧义答案；题干不靠文字陷阱制造难度。
3. 三个选项长度接近，错误选项看得懂，但不会传播另一个假事实。
4. 解释为一至两句，先讲答案，再给一个有意思的原因或背景。
5. 知识相对稳定，不依赖新闻、纪录、物种数量等频繁变化的数据。
6. 不含医疗建议、惊悚细节、歧视刻板印象或文化优劣判断。
7. 标记来源、核对日期和审核状态；来源改变或结论有争议时及时下线。

完整 100 道题及逐题来源见 [冷知识题库](./TRIVIA_QUESTION_BANK.md)：自然 34 题、动物 33 题、文化艺术 33 题。

## 无障碍与易用性要求

- 所有点击目标至少 48 × 48 CSS 像素。
- 页面支持 200% 缩放，不禁用浏览器缩放。
- 选择答案后，把焦点移到答案纸条标题；读屏先读正确答案，再读解释。
- 正确、已选择和当前焦点均同时使用文字或图形标记，不能只改变颜色。
- 支持键盘完成选择、继续、换玩法和退出。
- 尊重 `prefers-reduced-motion`；答案展开、亮窗和擦雾都有静态替代方式。
- 320 × 568 视口下不横向滚动，主要退出入口始终可到达。

## 验收标准

- 四种活动都能在进入游戏页后一次点击开始。
- 冷知识任意选项点击后立即出现正确答案、简短解释和可选来源。
- 随机抽题在仍有未看过题目时不会重复已看过题目，刷新或重新打开后仍然有效。
- 题柜准确显示 100 个抽屉及其看过状态，主动点击看过的抽屉仍可重温。
- 本地只持久化题目 ID，不保存答案正确性、用时或打开次数。
- 三词造句无需输入即可完整玩一轮。
- 全流程没有计分、连胜、限时、红色错误态或自动加难。
- 自动校验题库恰好为 100 题，类别数量为 34 / 33 / 33，ID 和类别内编号均不重复。
- 自动校验每题恰有三个不同选项、一个有效答案、解释、来源与核对日期。
- 断网时四种活动均可使用；点击来源失败不影响继续游戏。
- 刷新页面后不保留作答成绩或错误记录。
- 用户在感觉仍然存在时也能清楚地退出，不需要先确认“它退了”。

## 实现顺序

1. 完成 100 题内容复核，建立题库数据和自动校验测试。
2. 把现有“直接玩小游戏”改为四选一活动页，实现随机冷知识问答。
3. 实现 100 格题柜、看过状态和本地持久化，再补充清空标记入口。
4. 实现三词造句，并把四种活动的切换和退出方式统一。
5. 调整等待页退出文案和计时呈现。
6. 做移动端、键盘、读屏、缩放、减弱动态和离线回归测试。
7. 用 5 至 8 名目标用户做非医疗性质的可用性测试，重点观察题柜是否容易理解、是否产生完成压力，以及用户是否知道可以随时停下。
